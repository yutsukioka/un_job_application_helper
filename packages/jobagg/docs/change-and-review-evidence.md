## E2. Recovery

**Implementation/tests:** [host_recovery.py](../jobagg/pipelines/host_recovery.py) (`RecoveryPolicy`, `classify_failure`, `host_eligibility`), [remediation_worker.py](../jobagg/remediation_worker.py) (`retry_after_error`, `choose`, `claim`, listing reconciliation), [source_health.py](../jobagg/source_health.py) (`listing_recovery_pending`, `worker_source_health`); [test_host_recovery.py](../tests/test_host_recovery.py), [test_worker_dns_recovery.py](../tests/test_worker_dns_recovery.py), [test_worker_timeout_recovery.py](../tests/test_worker_timeout_recovery.py), [test_worker_vacancy_lifecycle.py](../tests/test_worker_vacancy_lifecycle.py), [test_source_health.py](../tests/test_source_health.py).

**Verified defaults, not new limits:** transient host recovery starts at 1,800 seconds and backs off up to 21,600 seconds, with a 900-second probe lease and at most three probes per rolling 86,400 seconds during the persisted recovery episode. A successful non-robots request closes that episode and retains its history; this is not a separate permanent daily quota for all host requests. Eligibility also respects Retry-After, host/source/task gates and quota history. A legacy or explicit `stopped` state does not expire automatically. Source health reports a review requirement and no predicted automatic attempt for those holds. Vacancy-specific retry rules and exact source contracts remain in the worker; they are not permission for general HTTP retries. See G1 for a mismatch between these layers.

**Incident:** [initial exact recovery](recovery-integration-evidence-2026-10-01.md#stale-source-recovery), [DNS follow-up](recovery-integration-evidence-2026-10-01.md#dns-recovery) and [final recovery journal](recovery-integration-evidence-2026-10-01.md#osce-recovery). These demonstrate evidence-pinned, selected-row recovery, not a reusable blanket reset. Recovery guards exist in the corresponding audit folders and are not all part of the standard package CI run.

**Recorded operating limits:** the [dispatcher configuration](recovery-integration-evidence-2026-10-01.md#validation-and-limits) bounds worker and publisher at 360 seconds each, with outer timeouts and a 100-task/80-detail/40-changed-job ceiling. The worker reserves reporting time; source configuration has its own admission and pacing limits. `live_publication.plan_publication` additionally selects at most five listing frames. These are current settings to preserve unless explicitly reviewed, not universal recommended values. Typed `SSLEOFError`/supported DNS and transport errors differ from `SSLCertVerificationError`; generic SSL and explicit URL-policy failures do not become retryable because a nested exception looks transient.

The deterministic checkpoint rejects nonverifying clients. The generic HTTP client still exposes a nonverifying option, so the requirement is not a claim that every possible caller is mechanically prevented from disabling TLS. [test_http_system_trust.py](../tests/test_http_system_trust.py) covers verified context construction and preservation.

## E7. Review scope

**User requirement:** the PR 121 guidance supplied in this session limits findings to issues newly introduced, newly apparent or worsened by the change, unmet explicit requirements, and broken behavior/compatibility/contracts. It excludes suggestions for general improvement or unrelated existing issues. P2-or-higher findings require concrete occurrence conditions, evidence, impact and why this change must fix them. Accepted/rejected findings are not repeated without new grounds or changed assumptions. The current policy request repeats that scope.

There is no automated check that can establish causal relevance, severity or adequacy of a human review. [CI](../../../.github/workflows/ci.yml) runs tests/security checks; those do not enforce the review-scoping judgment. The policy is linked from both agent instruction entry points and the package README.

## Enforcement gaps and decisions

| ID | Evidence or gap | Concrete follow-up / decision |
| --- | --- | --- |
| G1 | Deployed captured transient HTTP errors can create host cooldown while blocking their tasks. The transfer reproduced this mismatch before the narrow local fix. | The stacked recovery candidate promotes the 429/503 strict expected failures to passing regressions, checks all six supported statuses and capture/source/job binding, and verifies restart, Retry-After and rolling probe ceilings. See [portable defect evidence](recovery-integration-evidence-2026-10-01.md#captured-transient-response-integration-defect) and [retry tests](../tests/test_worker_timeout_recovery.py). This is prepared code, not a production activation. |
| G2 | `verify_listing` and source verifier APIs do not uniformly accept a deadline; surrounding worker/publication checks cannot prove every inner capture scan finishes within budget. | Add deadline propagation and a large-capture/interrupted-verification regression in a separate bounded change. Never downgrade an unfinished proof to complete. |
| G3 | Independent full-public-text coverage is not implemented for every source; attachment exclusion skips generic document discovery, so primary-document handling depends on the adapter. Direct PDF extraction does not prove page/image/table fidelity, and legacy `application_ready` can exist without current proof. | Add source-specific primary-document fixtures with attachments disabled, verify complete text/identity and preservation in both outputs, and keep unsupported coverage explicit. Relevant existing limits appear in [test_eu_primary_refresh.py](../tests/test_eu_primary_refresh.py), [test_complete_fetch_partial_main.py](../tests/test_complete_fetch_partial_main.py) and [test_complete_fetch_consolidation_gates.py](../tests/test_complete_fetch_consolidation_gates.py). Do not enable supplementary attachments as a shortcut or treat a legacy readiness flag as fresh verification. |
| G4 | Many exact activation/recovery guard tests and dispatcher code live in local `reports/`; standard package CI does not execute every audit guard. Local untracked evidence is not available from HEAD alone. | Decide which reusable guards/fixtures belong in the package/test suite before publishing the policy with a code change. Provide sanitized fixtures and reviewed code provenance; preserve private raw captures locally. |
| G5 | The five-listing-frame publication cap produced measured lag despite fresh worker observations. A queue position is a forecast, not a promise of completion after a fixed number of ticks. | Keep the current cap in this task. Any capacity/fairness change needs measured planning/export time, deadline and memory/storage regression coverage under R6. |
| G6 | IP-based blocking, the exact provider rule behind Chromium's denial, and universal transport superiority were not established. | Do not encode these hypotheses or the diagnostic workaround as general policy. A new source/phase needs its own evidence and bounded validation. |
| G7 | Review relevance, complete all-source main text, and a useful recovery explanation cannot be proven by documentation links or aggregate test counts. | Human review remains required. A future automated hold audit should check task/host consistency and explicit automatic-vs-review recovery without clearing holds. No arbitrary age threshold is prescribed. |

The policy reduces ambiguity; it does not eliminate provider changes, network failures, unknown completeness gaps or incorrect implementations. Existing regression coverage and new gaps must be reported separately.
