## Implemented boundaries

Legacy acceptance now distinguishes an intact bundle missing historical attempt
identities or implementation review from contradictory evidence. Known proof
deficits become durable repair records and insert no accepted exits. Changed
hashes, duplicate identities, wrong scopes and malformed bindings still stop the
ordinary import. Successful exits are checked even when a publication intent
already exists; publication success does not replace worker acceptance.

The catalogue consumes the publication classifier's actual path API and binds
its original classification hashes, rather than rehashing changed evidence into
a new claim. An explicit pre-activation, owner-held review can retain an exact
former-root relocation or reproduce and quarantine a publication contradiction.
Neither API rewrites historical paths, changes owners, approves an implementation,
certifies publication, or releases a hold. Contradictions cannot be closed by the
ordinary current-readback closure API. Native control fences include the review
records. These APIs are preparation operations, not automatic startup migrations.

Auxiliary artifacts can be retained by exact file identity with a **null content
hash and an explicit unverified-content hold**. This inventories large history
without parsing or certifying it. Changed identities stop checkpointing. Such
records are control sets, not accepted attempts or provider tasks.

Historical PID reuse is checked against the kernel boot boundary or observed
process start time. A surviving group without its leader, a possibly live worker,
or unavailable identity remains a stop. Darwin uses the SDK's `proc_pidinfo`
structure without executing setuid `ps` inside the sandbox. Only signal zero is
used for liveness checks; no production process was terminated.

`publication_bootstrap` adds an explicit owner-bound current-export preparation
API. It uses the existing export producer and durable preimage/replacement
journals, validates native destination clocks, checkpoints finite pages and seals
all four required exports for every destination. Prior pages are checked by their
sealed identities; changed stores, exports, receipts and unrelated owners fail.
The result proves current exports, not historical acceptance or an empty backlog.

Export rendering, SQLite work and ordinary file verification inherit cooperative
inner deadlines. Mid-export expiry reports resumable pending work and retains
journals/escrow. Byte limits apply before writing encoded export data. Individual
OS operations still require the existing hard outer supervisor; this is not an
OS disk quota or a universal bound on unrelated archived-artifact readers.
