# IOM application page inspection

Use this as a coverage guide, not a stored form schema. The actual vacancy's
rendered pages control. Record the current labels, choices and limitations; do
not carry applicant values or old application answers between runs.

Perform live inspection through Codex Browser only, following the
[browser requirement](../SKILL.md#browser-requirement) and shared browser
contract. The documented unified-runtime browser surface is permitted; desktop
Computer Use is excluded. If Codex Browser is unavailable, retain the unverified
scope and continue only work supported by existing artifacts.

## Personal Info

Read Contact Information, Address and Sensitive Personal Information instructions.
Record name capitalization guidance, contact fields, address dependencies, date
format and nationality/national-identifier structure. Existing identifiers can be
masked; do not unmask or transcribe their values merely to inspect the schema.
Preserve identity and contact fields during ordinary Phase 8 narrative entry.

## Experience and Education

Inventory all record headers and counts. Inspect representative existing editors
to establish the schema, closing them with Cancel; mark the sampling scope. Before
entry, inspect every requested record individually. An observed experience editor
may include employer/title/dates/current-job, country/city, Responsibilities,
appointment type, Achievements, Direct Reports, grade, supervisor contact and
contact objection, Reason for Leaving, Working Percentage, step and company URL.
Do not confuse working percentage or experience years with proficiency.

Keep Responsibilities and Achievements as separate field payloads. Headings used
to organize a generated artifact are not part of those fields. If Direct Reports
is numeric, separate the supported count from narrative staff-type explanations.
Do not reinterpret an input's technical string length as a permitted headcount.

Education may contain Degree, Major, School, dates, country/city, highest-degree
selection, free-text school-name fallback and completion status. Preserve exact
degree titles and status. A disabled degree control is not authorization to
delete/recreate a record. Note instructions allowing only one highest-degree
record without changing the selection in inspection mode.

## More About You

Read the language guidance and current skill catalog link. A catalog guides
labels; its presence does not prove that the input is a controlled dropdown.

Record language dimensions independently. One observed form uses Reading,
Writing and Speaking choices Advanced / Basic / Expert / Intermediate / Not
Applicable, plus Native and Study Language as No / Yes. These are example labels
to verify, not a conversion from another organization's proficiency scale.

One observed Skills editor uses a free-text Skill, Years of Experience, and Skill
Type with Adaptation / Communication / Hard Skill / Leadership / Persuasion /
Problem Solving / Soft Skill / Teamwork / Time Management. It has no proficiency
rating field. If this schema is present, prepare those fields and evidence-based
years using supported non-overlapping intervals; keep uncertainty outside clean
values. Do not invent a certification editor if none is shown.

## Job Application Questions and Attachments

Read every question, instructions, answer choices, attachment areas, diversity
field, opt-ins and expanded signature terms. Questions can use single-select
button pills although accessibility represents them as checkboxes. Verify the
actual cardinality, and keep option labels distinct from current selections.

Classify job-evidence questions separately from work rights, nationality, prior
service, family relationships, sourcing, disciplinary/criminal history and other
personal declarations. Do not answer personal declarations from the CV or infer
No from an empty control. Leave completeness certification to the user.

Record accepted file types and any size/count constraints from live guidance.
CV and cover letter may share Supporting Documents and URLs; a separate
Miscellaneous Documents section can require the highest-degree certificate.
Missing HTML `required` does not cancel mandatory wording in the instructions.
Check filenames and, for authorized replacements, document contents for the
correct vacancy. Retain unrelated supporting documents.

Read expanded E-Signature wording and guidance, but do not enter a signature or
activate Submit. Final declarations may exist inside the question block as well
as beside Submit. End with the draft accessible for the user's own review.

## Coverage and change handling

For each field record: page/section, exact label, control, allowed options and
selection count, required status and evidence, numeric limit/counting unit and
evidence, conditional trigger, Phase 8/source mapping, and observation date.
Use `UNKNOWN` for an unverified property and `UNOBSERVED_CONDITIONAL` for a branch
that would require changing an answer. Do not trigger validation or submit just
to learn constraints. Inspectors can prepare a useful handoff with those gaps.

Before changing a subsequent application, refresh the page list and affected
editors. A fifth page, different question order, changed required answer, new
choice or changed length invalidates only the corresponding prior mapping.
Keep unchanged verified material and update affected artifacts. Never claim all
conditional branches or every record body was read after sampling one editor.
